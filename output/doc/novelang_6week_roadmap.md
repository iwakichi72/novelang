# Novelang 6週間ロードマップ

作成日: 2026-02-03

前提: リポジトリ内のPRD/進捗を基に、MVPの現状とβバックログを6週間に再配分。

## 現状サマリー
- 基盤: Next.js App Router + TypeScript + Tailwind。Supabase (Postgres + Auth + RLS) を使用。
- 完了済み: 認証(Google)、作品一覧/詳細、読書画面、英語量スライダー、文タップ日英切替、辞書ポップアップ、AI辞書キャッシュ、単語帳CRUD、進捗保存/復元。
- 未完了: Vercel本番デプロイ、TTS、ストリーク、統計、オンボーディング、オフライン、Apple Sign-In、手動しおり。
- パイプライン: ingest/seedスクリプトで作品投入と文難易度スコア算出は実装済み。

## マイルストーン
- M1 (週2): MVP公開準備完了 (本番デプロイ + 主要ユーザーフロー完走)。
- M2 (週4): β主要体験の拡張 (TTS + ストリーク + 統計 + 手動しおり)。
- M3 (週6): 安定運用と拡張基盤 (オンボーディング + オフライン + Apple Sign-In + 追加コンテンツ)。

## 週ごとのゴールと成果物詳細
- 週1: 本番運用の最小保証(デプロイ、環境変数、監視導線)を確立。
- 週2: 新規ユーザーの導線を完成させ、初回読書までの離脱を削減。
- 週3: TTSで「読む→詰まる→助ける」の体験を音声面でも補強。
- 週4: 継続の可視化(ストリーク/統計)で定着率を改善。
- 週5: オフラインでの継続利用を支え、通勤や機内などに対応。
- 週6: Appleログインで獲得チャネルを拡大し、作品量を増やして継続率を押し上げる。

## 依存関係
- Vercel環境変数: Supabase URL/Key、Bedrock等のAPIキー。
- Apple Sign-In: Apple Developer Program登録とService ID/Keyの発行。
- TTS: Web Speech APIのブラウザ対応差分(特にiOS Safari)。
- オフライン: Service Workerのキャッシュ戦略(章/文/辞書データの粒度)。
- コンテンツ: ingest/seedパイプラインの安定運用と翻訳品質。

## リスクと対策
- 著作権: PD作品のみで開始し、出典とライセンス表記を明確化。
- 翻訳品質: 人手翻訳済みPD作品を優先。機械翻訳はフォールバック扱い。
- AIコスト: AI辞書呼び出しのキャッシュ強化とレート制限。
- 1人開発の遅延: 週次のスコープ固定と、UI/UXは段階的改善。
- ブラウザ差異: TTS/Service Workerの対応表を作成し、非対応時は機能トグル。

## 計測と成功基準
- 週間読書文数の増加。
- 初回読書完走率と7日継続率の改善。
- TTS/辞書の使用率と読書時間の増加。
